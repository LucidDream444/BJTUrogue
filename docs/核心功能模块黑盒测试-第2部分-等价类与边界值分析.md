## 一、模块范围与统一观察面

| 模块 | 核心功能 | 黑盒观察面 |
|---|---|---|
| M1 | 玩家移动、生命、护盾、受伤、恢复、掉落 | 位置、速度、HP、护盾、能量、死亡状态、掉落数量 |
| M2 | 武器射击、能量、冷却、弹丸与特殊效果 | 弹丸数量、敌人 HP、毒/减速状态、连锁/溅射结果、能量余额 |
| M3 | 敌人刷新、分裂、AI 接触伤害、帧伤 | 场上敌人数、队列长度、分裂数量、接触伤害次数 |

| M5 | 局外成长、结算、商店、存档迁移 | 币、统计值、商品库存、购买结果、存档版本、备份 |

统一输入域：

| 输入类别 | 有效范围 | 无效/健壮性值 |
|---|---|---|
| 整数计数 | `0..上限` | 负数、超过上限、小数、`NaN`、`Infinity` |
| 连续数值 | 有限且满足配置范围 | `NaN`、`±Infinity`、负数、超上限 |
| 时间 | `dt > 0`，逻辑时间单调 | `dt <= 0`、超大 delta、时间倒退 |
| 状态 | 存活/死亡、暂停/冻结、保护期、战斗/清房 | 非法状态组合 |
| ID/字符串 | 非空、已存在、长度不超限 | 空串、纯空格、未知 ID、超长 ID |
| 集合 | 空、1 个、达到上限、上限以上 | 重复项、空项、容量溢出 |
| 随机 | 固定种子/固定随机序列 | 边界概率值、序列耗尽 |
| 存档 | 缺失、损坏、旧版本、当前版本 | 未来版本、迁移断链、迁移超步数 |

边界值统一采用：

- 整数：`b-1 / b / b+1`
- 时间：`deadline-1ms / deadline / deadline+1ms`
- 概率：`0 / 0.499999 / 0.5 / 0.649999 / 0.65 / ... / 1`
- 空值：缺失、空串、纯空格
- 状态组合：有效前置、临界前置、非法前置

## 三、M2：武器射击与伤害效果

规则来源：`client/public/config/combat.json`、`client/src/domains/combat/WeaponMechanics.ts`、`Weapons.ts`。

### 3.1 武器边界基准

| 武器 | 能量消耗 | 基础冷却 | 特殊机制 |
|---|---:|---:|---|
| pencil | 2 | 250ms | 普通单发 |
| pulse | 18 | 1200ms | 连锁 2 个目标，半径 190，比例 0.28 |
| venom | 10 | 575ms | 500ms 一跳，10 跳，持续 5000ms |
| flare | 16 | 950ms | 溅射半径 92，邻近 60% |
| rail | 14 | 1100ms | 最多穿透 3 个目标 |
| smg | 1.5 | 105ms | 减速 25%，持续 1200ms |

基础子弹伤害公式：`10 × damageScale`。  
冷却公式：`250ms × cooldownScale`。

## 四、M3：敌人刷新、分裂、接触伤害与帧伤

规则来源：`client/public/config/balance.json`、`client/public/config/enemies.json`、`client/src/domains/enemies/spawn/SpawnQueue.ts`、`splitFan.ts`、`MinionSpawnPolicy.ts`、`client/src/domains/enemies/contact/ContactResolver.ts`、`client/src/core/actor/damage.ts`。

关键数值：

- 单帧最多刷新：`8`
- 溢出整队推迟：`40ms`
- 软上限：`180`
- 硬上限：`260`
- 队列最大年龄：`8000ms`
- 队列最大长度：`512`
- 帧伤 tick：`100ms`
- 配对 TTL：`250ms`
- 默认单源最多：`8 tick`
- 接触伤害上限：`100000 tick`

### 4.1 等价类

| 编号 | 输入/前置条件 | 类 | 预期可观察结果 |
|---|---|---|---|
| EC-M3-01 | 请求入队，`atMs>nowMs` | 有效 | 进入队列，未到期不刷出 |
| EC-M3-02 | 请求已到期，数量不超过单帧上限 | 有效 | 按 `atMs` 顺序刷出，最多 8 个 |

## 七、第 3 部分用例映射策略

建议不要为了接近 1000 条而硬凑。按当前模块划分，设计 **150—180 条**黑盒用例即可覆盖主要风险，仍在用户要求的 30—1000 条范围内。

### 7.1 建议分配

| 模块 | 建议用例数 | 重点 |
|---|---:|---|
| M1 玩家 | 30 | 移动、护盾溢出、保护期、催化液、掉落、满资源拾取 |
| M2 武器 | 35 | 六种武器、冷却/能量边界、毒、连锁、溅射、穿透、减速 |
| M3 敌人 | 30 | 队列三道闸门、分裂链、TTL、帧伤去重、对象池 |
| M4 地牢 | 25 | 种子复现、可达性、门状态、清房、传送、配置越界 |
| M5 局外 | 30 | 结算、幂等、购买顺序、退款、迁移、损坏档 |
| 跨模块场景 | 15—20 | 战斗→清房→传送→结算→商店→存档完整链路 |
| **合计** | **165—180** | 不含重复执行组合 |

### 7.2 用例字段模板

| 字段 | 内容 |
|---|---|
| 用例 ID | `TC-M1-001`、`TC-M2-001` ... |
| 模块 | M1—M5 |
| 标题 | 一句话说明测试意图 |
| 前置条件 | 玩家状态、敌人状态、地图状态、存档版本、随机种子 |
| 输入 | 按键、时间推进、伤害值、商店操作、存档内容 |
| 操作步骤 | 可复现的最短步骤 |
| 预期结果 | 可观察的数值/状态/错误信息 |
| 覆盖 | `EC-M1-03 / BV-M1-03` |
| 优先级 | P0/P1/P2 |
| 类型 | 正常、边界、异常、状态组合、幂等、回归 |

### 7.3 覆盖原则

1. **每个有效等价类至少 1 条正常用例。**
2. **每个无效等价类至少 1 条异常用例。**
3. **每个数值边界至少覆盖 `b-1 / b / b+1`。**
4. **时间类边界必须使用逻辑时间，不用真实等待。**
5. **状态组合采用判定表 + 成对组合，不做全排列爆炸。**
6. **随机逻辑必须可注入固定随机序列或种子，否则不可重复。**
7. **涉及 Phaser 的模块，优先通过测试场和可观察状态验证；纯逻辑保持在 Vitest `node` 环境。**
8. **每个用例只断言外部可观察结果，不直接断言私有字段或内部调用次数。**

## 八、待确认需求与文档漂移

以下只列为“待核实”，**不在本轮直接认定 Bug**：

1. `floors.json` 注释称八张图 footprint 均为 `(0,0,263,73)`，但 `floor-plan.json` 实际为 `(0,0,190,60)`。
2. `rooms.json` 部分注释仍写“16 间房”或“15 间”，6F 实测为 `rooms=18`、`roomTotal=19`。
3. `docs/地牢生成设计.md` 仍描述一局固定 15 间房，与当前八层流程和楼层平面图不一致。
4. `docs/局外成长设计.md` 仍写存档 schema v5，实际当前为 v6。
5. 默认显示模式旧草图写全屏，实际为窗口模式；代码注释说明是有意偏离浏览器限制，应统一文档表述。
6. 需求文档旧“拾取金币”描述与 2026-11-05 新增的双层货币/商店规则冲突，应以明确标注“新增需求”的 §4.7 为准。
7. `ShopRun.ensureStock()` 对 `shopId` 做 `trim()`，但 `purchase()` 使用原始 `shopId` 查找；前后空格是否应视为同一商店，需要明确。
8. `RunResultCommitter` 对 `runId` 的重复检查发生在空字符串校验之前；空 `runId` 不会命中缓存，但重复 ID 允许直接返回，建议明确该行为的验收口径。
9. 普通伤害路径对 `NaN/Infinity` 的拒绝契约未明确；催化液和恢复路径有有限值检查，普通 `takeHit` 未显式看到同等检查，需作为健壮性边界核实。
10. 移动时间步 `dt` 为 `NaN/Infinity` 时的行为未明确；项目只明确要求钳制超大 delta，需确认非有限值是否统一按 0 处理。
