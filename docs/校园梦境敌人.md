# 校园梦境敌人接入与验收

2026-11-02，D3。实现属于 `add-campus-nightmare-content`；配置与共享契约由主集成负责，客户端依赖版本保持原值。

## 番鸭

正式类型为 `muscovy`，配置在 `client/public/config/enemies.json` 的同名条目。`charge` 管理发动范围、蓄力、冲刺速度和距离、恢复、结束后的冷却及伤害。以 hpMode/hpValue 及现有难度系数派生血量，配置中不增加 maxHp 或内嵌难度。

蓄力开始锁定当时指向玩家的方向并画固定预警线；冲刺期间不追踪。每次攻击使用独立来源、目标重生身份与命中集合，对实际路径上的其他单位每个只命中一次。冲刺穿过动态单位，保留对墙、家具、关闭门和世界边界的阻挡；先截断位置，再结算截断线段的命中，墙后目标不受伤。攻击全部阶段按原规则受伤，结束或取消后才计算完整冷却。

纯逻辑在 `brains/MuscovyBrain.ts` 与 `charge/ChargeSweep.ts`。运行时位置仍以 Arcade body 为真值；高速扫掠在本步校正 body，不只改下一步速度。D1 从地形/当前门状态注入 `EnemySystemNavOptions.solidHitTime`；D3 白箱可使用公开 `setChargeGeometryQuery()` 注入矩形几何。

## 黑化猫

正式类型为 `nightmare_cat`，`vortex` 分别配置发动/蓄力/持续/恢复/冷却、伤害及节拍、伤害/吸引/偏弹半径、轻吸速度/总上限、转向率/总上限、容量和正常化退场时长。

蓄力后固定圆心旋转，圆内其他玩家和敌人（包括首领）周期受伤；圆形伤害不额外做墙体视线遮挡。吸力尊重实体碰撞，不拉穿墙；已承诺的番鸭 dash、猫 spin、甩出和抓取专用控制优先于外力。双方飞行子弹使用共享偏转函数，保持速率、阵营、伤害、寿命和命中记录；瞬时射线、近战和地面效果不参与。

`vortex/VortexField.ts` 在 WORLD_STEP 用开始时间锚定公共刻度；首刻度有效，每来源/目标每渲染帧至多一跳，长帧丢弃错过刻度。重入不重置节拍，无旧接触账本八跳上限或 TTL 截断。主入口的 `fixedStep:false` 保留，因此 WORLD_STEP 不是固定60Hz。

旋转时同时设置 `body.immovable=true` 和 `body.pushable=false`。Phaser 3.90 的圆形分离仅设 immovable 仍可能推动实体；该行为已通过真实浏览器复现并修正。结束、死亡及回池恢复原策略。死亡立即撤掉自身场，发布一次既有死亡结果；`CatPurificationFx` 用有容量上限的无物理副本播放褪黑、正常猫和入虚空，不占活敌人数，也不重复掉落。

## 契约与其他域跟随事项

- D1：订阅 `enemy_attack_requested`，校验玩家目标/重生身份后当步唯一进入自己的受伤模型；D3 新攻击不另调玩家 takeHit。玩家和 Weapons 消费 `enemy_vortex_started/ended`，使用 `core/vortex.ts`，控制速度不得累计上一帧外力。
- D1/D2：正式地图提供半径感知的最早阻挡查询，合并地形与当前启用门挡板；玩家与敌人碰撞 process 使用 `collidesWithUnits()`，仅 dash 穿动态单位。换层调 `clearVortices()`，最终回收用 `despawnAll()`，后者不模拟击杀。
- D4：图鉴新增两种独立类型并说明互伤/固定方向/偏弹/正常化退场。清单中动物、首领、风效和虚空入口使用真实资源。
- 资源：`MUSCOVY_ART` 四向每方向32帧，`NIGHTMARE_CAT_ART` 42帧，两个特效各8帧；`BOSS_FIRST_ART` 独立32帧，不再借最终 poison 槽。第二/最终首领使用原 key 的真实16帧图集，按阶段驱动。最终 poison PNG 保留资源用途，本次未凭空新增一套毒场战斗机制。

- `/test.html?arena=d3_campus_animals`：显示编号、状态、冷却、固定冲刺预警及双猫范围；I 切假玩家无敌，B 同发蓝色假玩家示范弹与真实敌弹，R 重置。该场的蓝弹是专用测试探针，正式 D1 Weapons 仍由产品联调验证。
- `/test.html?arena=d3_campus_art`：四类既有校园普通怪、独立菌菇/霜翼/心魔动画；P 观察纸团分裂，R 重置。
- `npm.cmd run test:run -- --no-file-parallelism src/domains/enemies src/core/actor/damage.test.ts src/test/architecture.test.ts`：19个文件、323项通过（含30/60/144Hz刻度一致、高速多目标、地形截断、池复用、多场清理及敌弹属性保持）。typecheck 与 D3 ESLint 通过。

真实 Edge/CDP 证据及可复跑脚本在 `artifacts/dream_20261102/d3/`。实测番鸭半径24面对 x=630 的墙停止于 x=606，墙前目标掉26血、墙后不掉血，结束时完整冷却2800ms。双猫各百余旋转采样只有一个圆心；单猫死亡使场数2→1，退场副本不带 body；清场后为0，池复用不继承来源和不可推动标记。真实敌弹偏转保持190速率，假玩家探针偏转保持520速率。

复跑前先在 client 启动 Vite（示例端口5175），另用独立临时用户目录启动 headless Edge 的9225调试端口；本机需 `--no-sandbox --disable-gpu-sandbox --in-process-gpu --disable-gpu` 绕过受限测试环境的GPU子进程启动失败。脚本使用 Node 原生 WebSocket（本机 Node24；不改变项目锁定的 Node20目标），不安装依赖、不使用日常浏览器资料。执行：

```powershell
node artifacts/dream_20261102/d3/verify-browser.mjs
```

可用 `D3_BASE_URL`、`D3_CDP_URL` 指定本地服务与独立调试浏览器。脚本新建自己的测试页，复查墙/开关门、双猫固定中心及死亡清理、双方偏轨、首领真图，并把 JSON 与1280×720截图写回证据目录。

## 正式产品联调回归

以下使用正常 `battle` 场景、真实 CombatSession/Player/Weapons 和 C1，不以白箱假玩家替代。证据位于同一 `artifacts/dream_20261102/d3/` 目录；原始 JSON 保留采样数据，截图和原生 CDP 脚本可供本地复查。

- `product-player-initial.json`：真实旋风发出4次8点伤害请求，现有玩家无敌帧接受其中2次，合计16点分别扣护盾5点、生命11点；玩家位置受轻吸而变化。没有重复受伤入口。
- `product-player-projectiles.json`：实际 D1 铅笔子弹轨道改变，速率520、伤害10、寿命900ms、出生时间及身份保持；24发实际 D3 敌弹同样偏转并保持190速率。静止玩家的控制速度保持0，吸引速度随距离变化而不回灌累计。
- `product-liquid-grab-cleanup.json`：真实喷液保留1.55速度倍率及穿敌规则；真实抓取暂停60帧期间逻辑时间、液体移动/静止计时和攻击请求均不增长，解除后恢复。调用实际换层入口后双方旋风、子弹和液体清空，液体倍率恢复1，不额外计击杀。
- `product-death-order.json`：真实第八层最终首领与玩家在同一物理帧死亡，分别验证首领先死、C1玩家先死、普通怪先死再首领/玩家死亡。三种顺序均经过真实受伤模型与 BattleScene 归并，结果为 `dead`、`settlement`，没有结局动画请求；伤害阶段没有提前顿帧。普通怪击杀仍在 `POST_UPDATE` 冻结45ms，时钟推进后恢复，保持打击感。
- 同一 JSON 的 `athleteDash`：正式 athlete 角色、等级1技能，按D使控制/实际速度达到150，发动180px突进。突进中控制速度清零而D仍按住；突进中松D后推进真实时钟、物理和技能帧，结束时控制速度与 body 速度均为0，没有旧移动惯性回弹。

同帧死亡及普通击杀顿帧可复跑：

```powershell
node artifacts/dream_20261102/d3/verify-product-death-order.mjs
```

主集成另已验证三名角色的正式产品入口、第八层实际首领死亡、各自结局与结算流程。上述 D3 联调未出现运行时异常；无用户点击的独立无头浏览器会出现预期的音频未解锁警告。
