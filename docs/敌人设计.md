# 一、分裂怪

# 分裂怪（splitter）完整规格 — 「一击必杀、连锁分裂的蜂群」

## 1. 定位与威胁分级
- 威胁级别 2/5：单体弱、数量压力大，教玩家「边退边打、用穿透/范围武器清群」。
- 全代际一击必杀（基线武器 1 发），爽点在「一枪一个 + 连锁分裂全清」的连击节奏，不在单体强度。
- 实现文件：`client/src/domains/enemies/actors/SplitterActor.ts`、`client/src/domains/enemies/brains/SplitterBrain.ts`（纯逻辑）。

## 2. 三代数值（数值在 enemies.json，此处为派生结果）
| 代 | 贴图 key / 画布 | 碰撞半径 | HP（普通） | 速度 px/s | 接触帧伤/100ms | 分裂出 | 分裂延迟 | 命中顿帧 | 击杀 trauma | 死亡粒子 |
|---|---|---|---|---|---|---|---|---|---|---|
| t1 (gen0) | `enemy_splitter_t1_idle` / 48 | 18 | 7 | 62 | 6 | 2 × t2 | 180ms | 45ms | 0.20 | 10 |
| t2 (gen1) | `enemy_splitter_t2_idle` / 32 | 12 | 5 | 92 | 4 | 4 × t3 | 160ms | 25ms | 0.10 | 7 |
| t3 (gen2) | `enemy_splitter_t3_idle` / 24 | 8 | 3 | 120 | 3 | 无 | — | 0ms | 0.05 | 5 |

- HP 由 loader 从 `hpValue`（shots 单位 0.7/0.5/0.3）派生：`hp = clamp(round_half_up(hpValue × 基线子弹伤害 × 难度 enemyHp), 1, floor(基线子弹伤害 × 0.75))`。普通 7/5/3，简单 6/4/3，困难被余量钳制为 7/7/4 — 三种难度下都保持「基线 1 发击杀」，难度只改玩家容错不改操作节奏。
- 速度受难度 `enemySpeed` 乘数（0.9/1.0/1.1），接触伤害受 `enemyDamage` 乘数（0.6/1.0/1.3）。
- 物理体：圆 `setCircle(radius, S/2 − radius, S/2 − radius)`，S 为当前画布边长；每次跨代换贴图后必须重设 offset，否则沿用旧 offset 导致判定偏心（源码事实：`Body.setCircle` 不传 offset 会保留旧值）。

## 3. AI 行为（FSM：`idle → seek → flinch → dying → dead`）
- 纯逻辑函数/类：`SplitterBrain.tick(ctx: BrainContext): BrainOutput`，不 import Phaser；输出 `{ vx, vy, state? }` 速度意图，位置真值永远是 Arcade body。
- `idle`：索敌半径 340px 内无玩家时，围绕出生锚点 48px 范围内漫步（远档 5Hz）。
- `seek`：`vx,vy = normalize(player − self) × speed × slowMult`；分离力用空间哈希（`NeighborQuery` 接口，实现由 D3 提供，`hash.rebuild(agents)` 每 tick 一次，查询半径 = 两半径和 + 4px）。
- `flinch`：每次非击杀受击进入 90ms：速度清零 + 挤压动画；不可打断 seek 以外的任何行为（无攻击前摇——接触型敌人靠 P2 的「减速叠层 + 分裂延迟」提供可读性）。
- `dying`：受击杀后立即 `body.checkCollision.none = true`、速度清零、进入死亡动画并结算分裂（见第 4 节），动画时长 = 该代 `splitDelayMs`。
- AI LOD：距玩家 < 340px 走 30Hz 完整 AI，≥ 340px 走 5Hz 直线移动；错峰调度 `(aiFrame + actor.instanceIndex) % stride === 0`，不得每帧更新全部实体。
- 与玩家接触：`contactDamagePerTick`（6/4/3）经帧伤账本每 100ms 结算一次（源 = 敌人 id，`sourceKind: 'contact'`，目标 = 玩家 ActorModel）；玩家侧减伤/无敌帧由 D1 的 takeHit 处置。

## 4. 分裂时序（毫秒级，全部分裂只入队、在 POST_UPDATE 统一生成）
1. T+0：takeHit 返回 `killed:true` → 状态 `dying`，`checkCollision.none = true`，`Bus.emit('entity_killed', …)`；用 `SpawnQueue.enqueueSplit(parent, children, nowMs)` 登记，分裂触发时刻 = T + `splitDelayMs`（t1=180、t2=160）。
2. T+splitDelayMs：按父体当前位置与受击方向 `impactDir` 计算子体落点：`childAngle = atan2(impactDir) ± fanAngleDeg/2`（t1 扇形 60°，t2 扇形 110°；无受击方向时用 `rng` 随机角），落点 = 父体位置 + 方向 × `spawnRadius`（22/16）。
3. 子体 i（i=0,1,…）在 T + splitDelayMs + i × `spawnStaggerMs`（90ms）生成；全局节流：`maxSpawnsPerFrame = 8`，超出的排入 pending 队列按 `overflowStaggerMs = 40ms` 顺延——**永不丢弃任何子体**，pending 数计入清房判定。
4. 子体生成：池 acquire → `setTexture(childKey)` → `setCircle(r, S/2−r, S/2−r)` → `body.reset(x,y)` → 状态 `idle`，`graceUntilMs = nowMs + graceMs(220)`。grace 期间允许移动但速度 ×0.5，且**不登记接触帧伤账本**（免疫「贴脸开壳」）。
5. 链上限：t1 死 → 2 × t2，每只 t2 死 → 4 × t3，单族总量 1+2+8 = 11 只，t3 死后不再分裂。
6. 池压力：每个「实体/帧」的生成只走 `EnemyPool.acquire`；池满时子体顺延等待（SpawnQueue 是唯一出口，不会 override 回收任何存活实体）。
   ⚠️ **饱和语义必须写死，否则「T + splitDelayMs 分裂」这条时序契约会在压力下静默失效**：**同屏存活上限 = `poolCapacity`（默认 512），这就是硬上限**，不存在「512 之上还能再撑到 640」这回事（初版池容量 512 与「允许溢出」两种说法互相矛盾）。**SpawnQueue 饱和时生成延迟无上界**、pending 是单调 FIFO；`d3/swarm_stress` 按 1→2→8 换算最多会产生约 3000 个待生成子体，全都压在 pending 里，此时「按时分裂」不再成立——**这是被接受的降级，但必须在 HUD 上把 pending 数暴露出来**，不能让测试场看起来正常而实际早已饱和。
   **清房判定只依赖 pending 计数，不依赖分裂延迟上界**（否则饱和时房间永远清不掉）。`swarm_stress` 支持 per-arena 覆盖 `poolCapacity`（建议 ≥ 2048）或只生成 t3，避免用「生成风暴」这一最坏用例去撞默认上限。

## 5. 表现与音效（触发时机全落在事件上）
- 受击（每次 takeHit applied>0）：60ms `setTintFill(0xffffff)` → `clearTint`；挤压 tween `scale(1.3, 0.7) → (1,1)` 90ms（10Hz 门控，高频连击不叠加）。
- 命中顿帧：`JuiceDirector.requestHitstop(gen0=45ms / gen1=25ms / gen2=0)`，滚动预算（500ms 窗口内顿帧总量 ≤ 12% 实时）超支则跳过。
- 顿帧实现（唯一定定）：冻结 `core/time.ts` 的 `GameClock`（逻辑时钟停走、`clock.freeze(ms)`），**绝不碰 `physics.world.timeScale`**（源码事实：`msPerFrame = _frameTimeMS × timeScale`，`timeScale=0` 会让 `while (_elapsed >= 0) …` 死循环，且语义是反比：=2 才是半速）。
- 震屏：击杀 trauma +0.20/0.10/0.05（`JuiceDirector.addTrauma`，全局 cap 0.6，震屏起播最小间隔 90ms）。
- 分裂：每只子体诞生播放 `sfx_splitter_pop`，`detune = 代际 × 200` cents（t2 +200，t3 +400）——两级分裂音高递进；同时子体出生 pop tween `scale 0.4 → 1.0` 120ms。
- 击杀音：`sfx_splitter_hit`（8 实例固定池轮转，命中音 `detune` 随机 ±200 cents；t3 基础 +200）；连击（1200ms 窗口内连续击杀计数 ≥3）每级 +120 cents，上限 +720；连击 ≥7 触发 flourish：相机 flash(0xffffff, 0.6, 120ms) + 震屏 0.006/180ms + `sfx_kill_flourish`，随后连击归零。
- 死亡粒子：单粒子发射器（`maxParticles: 64` 显式设置），burst 10/7/5，白色调 gen 染色（t1 纯白、t2 0xf0e8ff、t3 0xffe8f0，仅影响观感）。

## 6. 反挫败设计
- 生成宽限 220ms：新分裂体不造成接触伤害，防止玩家近战清场时被贴脸秒。
- 分裂扇形向外（60°/110°）：从玩家射击方向的两侧散开，不直冲玩家脸。
- 死亡到分裂之间 160–180ms 的非实体窗口：玩家的下一枪可以提前调整站位，分裂不是「不可反应事件」。
- 任何难度、任何波次都保持「基线 1 发击杀」；困难只改血量到 7/7/4（仍在 1 发内）、伤害 1.3×、数量 1.25×。
- 表现降级（只降特效、不降玩法）：存活软阈值 180 → 关闭挤压/花式/顿帧对 gen1 生效；硬阈值 260 → gen1/gen2 顿帧与震屏全关、粒子 50%。任何情况下不跳过量产——生成永不被丢弃。

## 7. 事件与测试入口
- 发出：`entity_spawned { id, kind:'enemy', enemyKind:'splitter', gen, x, y }`、`entity_damaged { targetId, amount, hpAfter, sourceId, sourceKind, mode, batched, tickCount, frameId }`（tick 模式按 200ms 聚合发出）、`entity_killed { id, enemyKind:'splitter', gen, x, y, sourceId }`、`enemy_split { parentId, children:number[], parentGen, childGen }`。
- 测试场 `d3/splitter_chain`：按 K 击杀最近分裂怪触发完整链；HUD 显示各代存活数、SpawnQueue pending、连击数；鼠标点击 = 一次基线伤害（10）。\n

# 二、肉盾怪

# 巨型肉盾怪（tank）完整规格 — 「走位换输出窗口的装甲教具」

## 1. 定位与数值
- 威胁级别 4/5，精英级单体；设计目标 TTK = 10 秒（基线武器全命中），教会玩家「读前摇、拉开、抓恢复窗输出」。
- HP 由 loader 派生：`hp = round_half_up(ttkSeconds(10) × baselineDps(40) × contactFactor(1.30) × 难度 enemyHp)` → 普通 520；简单 442；困难 676。
- contactFactor 1.30 的来源：每发基线子弹对肉盾实际造成 13 点（10 冲击 + 穿透期间 1 次 3 点 tick），13/10 = 1.30 ∈ 验收包络 [1.00, 1.35]。
- 半径 40（画布 96，`enemy_tank_idle`），速度 52 px/s（受减速影响），接触帧伤 0（非贴身伤害型，伤害全部来自 slam）。
- 实现文件：`client/src/domains/enemies/actors/TankActor.ts`、`client/src/domains/enemies/brains/TankBrain.ts`（纯逻辑）。

## 2. 帧伤 tick 机制（D3 侧）与子弹/近战接触语义（跨域契约核心）
统一契约：`takeHit(req: HitRequest): HitResult`（定义在 `client/src/core/actor/damage.ts`）：
```ts
interface HitRequest {
  sourceId: number            // 单调递增、永不复用的数值 id（子弹 = shotId，敌人 = 实例 id，调试 = debugSeq）
  hitKey: string              // instant 模式同帧去重键，如 `bullet:${shotId}`
  mode: 'instant' | 'tick'    // instant=立即结算一次；tick=经账本按 100ms 节拍结算
  amount: number              // instant=最终伤害；tick=每 tick 伤害（调用方按 ratio 派生后传入）
  frameId: number             // 同一 frameId+hitKey 只结算一次
  sourceKind: 'bullet' | 'melee' | 'contact' | 'aoe'
  knockback?: { x: number; y: number; strength: number }
}
interface HitResult { applied: number; killed: boolean; consumed: boolean }  // consumed 告诉 D1 子弹是否该销毁
```
- **子弹 → 肉盾（`bullet` 语义，唯一定义）—「穿透」是这个怪的身份，不是特例**：**子弹不被消耗，穿透肉盾继续飞**。这正是它作为「重甲」该有的手感：绝大多数敌人挡下子弹，它挡不住、但有硬甲。步骤：(a) 首次接触的 overlap 回调内 `takeHit({ mode:'instant', amount: 子弹伤害(10), hitKey: 'bullet:'+shotId })` 结算**全额冲击**，`HitResult.consumed` 返回 **`false`**；(b) 同一回调内 `ledger.register(shotId, tankModel, { amountPerTick: round_half_up(10 × 0.25) = 3, maxTicks: 3, ttlMs: 250 })`——**只要子弹仍在肉盾体积内**，每 100ms 结算一次 3 点「穿透帧伤」，每次结算都触发受击动画与受击音效（`bullet.pierce: true` 表示该源不被消耗）。
- **D1 侧零特判**：D1 的子弹逻辑永远是同一句 `if (result.consumed) recycleBullet()`。肉盾返回 `false`，所以 D1 **不需要知道肉盾这个怪存在**，也不必写任何穿透分支——`consumed` 字段就是这个抽象层。
- **一发子弹对肉盾实际结算几次**：肉盾半径 40（直径 80），基线弹速 520px/s → 最坏（正中圆心）在体积内停留 `< 80/520 ≈ 154ms` → 100ms 节拍下**恰好 1 次穿透 tick**，偶发 2 次。所以常规情形每发恒 **13 点**，TTK 可精确核算到 10.0s；`maxTicksPerSource: 3`（上限 19 点）只是防「子弹与肉盾同向运动被长时间黏住」的兜底。
- **近战/持续型接触源 → 肉盾（`melee` 语义）**：overlap 回调持续刷新 `ledger.touch(sourceId, target, nowMs)`；每 100ms tick 结算 `amountPerTick = round_half_up(源伤害 × 0.25)`，`maxTicksPerSource: 8`（即同一接触源最多 8 tick，需中断重接），脱接触超过 `pairTtlMs: 250` 条目自动过期。
- **四条不变式**（写进代码并用 Vitest 锁死）：① 每个 (source, target) 配对每 tick 最多结算一次——每目标 `Map<number, TickEntry>` 以数值 sourceId 为键（**绝不用池槽位或位运算 pairKey**）；② 单帧最多推进一次 tick（用 `GameClock.frameId` 门控），`nextTickAtMs = nowMs + tickMs` 不追赶；③ 攻击源被回收时 `ledger.releaseSource(sourceId)` 清掉它的全部条目；④ **目标死亡或回池时必须 `ledger.releaseTarget(target)`**——否则池槽位复用后，旧子弹的 tick 会结算到新生成的敌人身上（「打到尸体上」）。目标侧另加一道保险：结算前校验 `entry.targetSpawnSeq === target.spawnSeq && target.alive`，不满足直接丢弃该条目。sourceId 与 spawnSeq 都单调递增、永不复用。
- **`frameId` 的来源（唯一定义）**：`HitRequest.frameId` 一律取 `core/time.ts` 的 **`GameClock.frameId`**——每个**渲染帧**自增一次的单调计数器，**在顿帧与暂停期间不自增**。这是账本不变式②「单帧最多推进一次 tick」的门控依据，**不允许任何调用方自己造帧号**（D1 构造子弹请求、ArenaBase 调试点击、敌人接触登记三方都必须取同一个源）。测试锁定三件事：同一 `frameId` + 两个不同 `hitKey` 都要结算；同一 `hitKey` 在同一 `frameId` 内重复调用只结算一次；跨 `frameId` 的同名 `hitKey` 正常结算。
- 账本挂载：订阅 `Phaser.Physics.Arcade.Events.WORLD_STEP`，回调内**忽略** `fixedDelta` 的秒值（仅当「物理步发生」信号），tick 推进用 `GameClock.nowMs`（毫秒）；测试锁定「单帧两次物理子步也只结算一次」「暂停（`physics.world.pause`，无 WORLD_STEP）时账本冻结」「恢复时 `nextTickAtMs = nowMs`，隐藏 30s 回来最多 1 tick」。
- 暂停语义（唯一定定）：暂停 = `scene.pause()` + `physics.world.pause()` + `clock.pause()`；恢复不清账本但重置所有 `nextTickAtMs = nowMs`，`Bus.emit('app_resumed')`。**顿帧（hitstop）与暂停同构**，只是自动恢复：`clock.freeze(ms)` 的同时 `physics.world.pause()`，到期 `world.resume()`。测试锁定：顿帧期间任一 body 位移为 0、无 `WORLD_STEP` 触发、账本不推进；隐藏 30s 回来最多 1 tick。
- 账本实现文件：`client/src/core/actor/damage.ts`（`DamageLedger` 类，零 Phaser 运行时依赖，可 node 直测），实例随世界创建一次（战斗场景由 D1 创建并注入 D3 敌人系统；测试场由 `ArenaBase` 创建）。

## 3. FSM 状态机（`idle → seek → windup → slam → recover → stagger → dying → dead`）
- `idle`：距离 > 480px（`aggroRadius`）或 > 620px（`loseTargetRadius`）回退；10Hz 慢速漫步。
- `seek`：朝玩家移动，速度 = 52 × slowMult × 难度 speed 乘数；距离 ≤ 96px 且冷却已好（`lastSlamEndMs + cooldownMs 2400`）→ `windup`。
- `windup` 700ms：停止移动；预警表现 = 红色预警环（Shape/Graphics 几何圆，无贴图），半径视觉 66 → 110px，alpha 0.15 → 0.55，全程线性；`sfx_tank_windup`（低音上扬，-200 cents，700ms）。玩家有完整 700ms 躲避窗口（满足 P2：降低挫败感）。被 stagger 打断时取消（不进 slam）。
- `slam`：以自身中心 110px 半径 AOE。命中玩家：`takeHit` instant 22 × 难度 damage 乘数 + 击退 240px/s（180ms）；顿帧 60ms（`clock.freeze`）；震屏 `JuiceDirector.shake(0.004, 220ms)`；尘土粒子 ≤16。音效 `sfx_tank_slam`（低音 -300 cents）。
- `recover` 900ms：不可移动、不可攻击、可被打——受伤 ×1.25（`vulnerableDamageMult`），这是玩家的输出窗口奖励。
- `stagger`：当减速叠层达到 12 时触发一次 800ms 硬直（后撤 60px/s，取消 windup、不打断 slam 生效帧）；`staggerCooldownMs 3000` 防止无限连控。
- `dying` 400ms：塌缩挤压 `scale(1.4, 0.6)` + tint 0x888888；结束粒子 burst 24 + `sfx_tank_death`（-300 cents）。

## 4. 受击减速模型
- 每次受击（instant 或 tick 结算均计）叠 1 层：`stacks = min(stacks + 1, 12)`，并刷新 `stackExpireMs = nowMs + 1500`。
- 速度乘数：`slowMult = max(minSpeedMult 0.25, speedMultPerStack 0.95 ^ stacks)`；12 层 → 0.540（52 → 28px/s）。连续射击下 1.2s 可达满层（10 次结算/秒时），停止命中后按 `decayIntervalMs = 1500/12 = 125ms` 每层递减，1.5s 完全恢复。
- 避免「罚站死」：0.25 地板 + stagger 冷却 + 玩家移速 200 可稳定拉出。

## 5. 防卡死（antiPin）
- `unstuckMs 400`：意图速度 > 0 但实际位移 < 2px/帧持续 400ms → 沿边境切向 ±90° 侧移 600ms（`lateralEscapeMs`）。
- `minDistFromPlayer 24px`：距玩家 < 24px 时停止向其移动，禁止把玩家顶进墙里或与玩家完全重叠。
- 转角脱困 600ms 上限后强制恢复 seek。

## 6. 音效节流（分层频率表，全部走 `domains/enemies/presentation/`）
| 通道 | 频率/间隔 | 说明 |
|---|---|---|
| 受击音 `sfx_tank_hit` | 最小间隔 250ms（4Hz） | 8 实例固定池轮转；期间命中静默累积 |
| 碾压音 `sfx_tank_grind` | 循环 | 只要存在活跃 tick 条目即循环播放（音量 0.3），条目清空后 120ms 淡出 |
| 受击闪光 | 10Hz/实体 | 光学闪光池，不逐 tick 闪 |
| 位置抖动 | 20Hz/实体 | 命中 ±2px 偏移 |
| 挤压 | 7Hz/实体 | 高频命中合并为一次 |
| 震屏 | 全局起播 ≥90ms 间隔 | 肉盾受击不震屏；只 slam/死亡震屏 |
| `entity_damaged`（tick）事件 | 200ms 聚合 | 携带 `batched:true, tickCount:n`，避免事件洪泛（飘字渲染归 D1） |
| 音高 | 随血量线性 | `detune = hpPitchCents(400) × (1 − hp/maxHp)`：越接近死亡装甲声越尖 |

## 2. Actor 基类（`core/actor/`，玩家与敌人同一种实体，D1 直接 extends）
```ts
// ActorModel.ts —— 纯逻辑，零 Phaser import
export type ActorKind = 'player' | 'enemy'
export interface ActorStats { maxHp: number; speed: number; radius: number }
export class ActorModel<S extends string = string> {
  id: number                       // 单调递增，实例创建时分配，永不复用（不是池槽位）
  spawnSeq: number                 // 每次 spawn 由单调计数器分配，池槽位复用后也不相同（账本不变式④用）
  kind: ActorKind
  stats: ActorStats
  hp = 0
  maxHp = 0
  state: S                         // 泛型：core 不认识任何域的状态集合
  velIntent = { x: 0, y: 0 }       // 只输出速度意图；位置真值永远是 Arcade body
  alive = true
  takeHit(req: HitRequest): HitResult   // 唯一的受击入口（玩家/敌人同路径；减伤/无敌帧在此）
  reset(stats: ActorStats): void
}
// 敌人域在自己的模块里收窄：export type EnemyState = 'idle'|'seek'|'flinch'|'dying'|'dead'
//                              class EnemyModel extends ActorModel<EnemyState> {}
// 玩家域同理：D1 用 ActorModel<'alive'|'dashing'|...>，与敌人共基类但状态集互不相干
// Actor.ts —— Phaser 表现与适配（子类化必须 declare body，AGENTS §8）
export class Actor extends Phaser.Physics.Arcade.Sprite {
  declare body: Phaser.Physics.Arcade.Body
  model!: ActorModel
  syncFromBody(): void             // 每 tick 把 body.center/velocity 回读进快照（逻辑不积分位置）
  applyVelocityIntent(): void      // body.setVelocity(velIntent.x, velIntent.y)
  park(): void                     // killAndHide + physics.world.disableBody(body)（唯一真摘 RTree 的方式）
  wake(x: number, y: number, radius: number, refSize: number): void
                                   // world.add(body) + setCircle(r, S/2−r, S/2−r) + body.reset(x,y) + setActive/Visible(true)
}
```
- `park()` 必须用 `physics.world.disableBody(body)`：源码事实——sprite 级 `disableBody(true,true)`（Enable.js）只置 `body.enable=false`，不摘 RTree；`body.enable=false` 同样每步仍被 `tree.load()` 插入；而 sprite 级 `enableBody(true,x,y,true,true)` 也不会重新加回 `world.bodies`，唤醒必须 `world.add(body)`。
- D1 扩展方式：`PlayerActor extends Actor`（core 基类），brain 由输入驱动；玩家专用逻辑走 `PlayerModel extends ActorModel`，不改基类。D1 的战斗场景创建 `DamageLedger` 并注入 `EnemySystem`。
- 池：`scene.physics.add.group({ classType: EnemyActor, maxSize: 512, runChildUpdate: false })`；预暖 `pool.createMultiple({ key, quantity, active:false, visible:false })` + 逐个 `park()`（源码事实：Group 无 `prewarm`；`maxSize` 默认 -1 不封顶；`get()` 找 `active===false` 所以回收必须同时动 active+visible）。

- 校验（手写校验器，不引新依赖）：`hpMode` 只能是 `'shots' | 'ttkSeconds'`；`tickMs > 0`；`childCount >= 0`；`textureKey` 必须存在于 `core/assetManifest.ts` 的清单；缺失字段报 `ConfigError` 并带字段路径。
- 派生公式（唯一真值）：
  - `hpMode:'shots'` → `hp = round_half_up(hpValue × 基线子弹伤害 × 难度enemyHp)`，**仅当条目声明 `oneShot: true` 时**再套余量上限 `min(hp, floor(基线子弹伤害 × 0.75))`
  - `hpMode:'ttkSeconds'` → `hp = round_half_up(ttkSeconds × baselineDps × contactFactor × 难度enemyHp)`
  - **余量上限为什么必须挂在 `oneShot` 上**：初版把它无条件套在所有 `shots` 条目上，等于给整个 `shots` 体系封了 7 点血的天花板——将来任何想表达「3 发击杀」的杂兵（`hpValue: 3` → 30）都会被静默钳成 7。一个本该服务「一击必杀」的特例规则，会反过来废掉这套血量表达方式的全部价值。契约测试只对分裂怪三代断言钳制结果，不对任意 `shots` 敌人断言。
- 难度乘数只存在于 `difficulty.json`（单一来源），enemies.json 禁止出现难度字段（契约测试断言）。
  - ⚠️ **归属待对齐**：《人员分工方案》§三 把「难度曲线：入门/普通/困难的数值差异」明确列为 **D1 的设计输出**。本稿由 D3 起草 `difficulty.json` 只是为了先让派生公式有输入。**冻结前必须与 D1 二选一定死**：要么 `difficulty.json` 并入 D1 签字的 `balance.json`，要么明确 D3 只提交「敌人侧需求与派生公式」、数值由 D1 拍。**在此之前契约测试只断言不变式**（任意难度下分裂怪一击必杀、肉盾 `TTK = ttkSeconds × baselineDps × contactFactor`），**不对具体乘数产物做快照断言**——否则 D1 调档位会把 D3 的测试全打红。
- 契约测试 `client/src/test/config.contract.test.ts`：用 `node:fs` 直接读 `client/public/config/*.json`（与生产同一份字节），断言分裂怪 7/5/3、肉盾 520、困难钳制 7/7/4、所有 textureKey 在清单内、无难度字段。
- 加载失败 = 停在明确错误页，**绝不静默取代码内默认值**（否则违反红线 2 的语义）。

  - **为什么不用「同 key」**（初版写法，已废弃）：`[源码]` `generateTexture(key,…)` 在 key 已存在且是 canvas 纹理时**是往同一张 canvas 上再画一次，不替换、不报错**。同 key 方案下，真美术文件到位后一旦漏掉一道守卫，真图会被白方块**静默覆盖**——而这类问题**只在接入真美术时才暴露**，那时已经没有上下文了。

  - **可测的守卫**：`architecture.test.ts` 扫描 `client/src/**`（`assets.ts` 与 `assetManifest.ts` 除外），断言源码里不存在资源清单中的 key 字符串字面量——硬编码会被 CI 拦下。

## 8. 引擎事实修订（D3 直接改 `docs/Phaser3性能与引擎事实.md`，同文件 owner）
- §2 修正：唤醒池中对象不能只用 sprite 级 `enableBody`（不加回 `world.bodies`）；须 `physics.world.add(body)` + `body.reset`。
- §3 修正：表内「`disableBody(true,true)` 会摘除 RTree」不准确——sprite 级只置 enable；真正摘除只有 `physics.world.disableBody(body)`。
- §5.3 修订：占位纹理采用同 key + 两道守卫方案（而非独立 `${key}__placeholder`），与 AGENTS §6 一致。
- §7 补充（2026-10-12 修订）：**本项目顿帧 = `clock.freeze(ms)` + `physics.world.pause()`，到期两者一起恢复；绝不碰 `physics.world.timeScale`。**
  初版只冻结 `GameClock` 是**不够的**——`GameClock` 只是各域自愿查询的包装器，物理积分、子弹位移、sprite 位置完全不受它影响，结果是「逻辑停了、画面照常动」，顿帧的视觉冲击基本不存在。
  而 `timeScale = 0` 是死路：`[源码]` `World.js` 里 `msPerFrame = _frameTimeMS × timeScale`，`while (_elapsed >= msPerFrame)` 在 `msPerFrame === 0` 时**永不退出**。`world.pause()` 是另一回事——`World.update()` 在 `isPaused` 时提前 return 且**不累积 `_elapsed`**，恢复后不会追赶补步，正是我们要的语义。
- 新增：`Body.setCircle` 不传 offset 保留旧值；`WORLD_STEP` 的 `fixedDelta` 单位是秒。

# 五、风险

- hpMode 派生血量依赖 D1 的基线武器数值，一旦基线被改动（伤害/射速/精度），所有敌人数值和 TTK 会整体漂移，必须在第 4 周冻结基线并让契约测试盯住。
- 分裂链「永不丢弃子体」的兜底只有表现降级（180/260 阈值），若真实设备上 260 只存活仍掉帧，阈值和降级层级需要真机实测二次校准。
- 帧伤账本正确性横跨 D1（子弹 shotId、releaseSource 调用）与 D3（登记、结算），任何一方绕过 takeHit 直接改 hp 都会静默破坏去重与配对语义，靠契约测试和 code review 双保险。
- **子弹穿透是玩家侧的隐性增益，必须知道它的边界**：一发子弹若一次穿过 N 只肉盾，会对每只都造成全额 13 点（同一发子弹打出 13N）。这是穿透语义的**必然**结果，不是 bug——但 D2 生成器若在狭长走廊里塞 4 只并排肉盾，那一发子弹的收益就是 52 点。**多肉盾房间的实际 TTK 会明显短于 10 秒**，这是设计上接受的（鼓励拉线走位），但数值评审时要按「同时存在的肉盾数」复核，不能只看单体。另外肉盾**不阻挡子弹**意味着它身后的敌人可被隔怪点杀，布阵时要考虑这一点。
- testing场里的「点击式基线伤害 + 无玩家」与真实战斗（移动射击、闪避、多方向弹幕）手感差异大，10 秒 TTK 与 700ms 预警需要 D1 战斗场景接通后做第二次手感校准。
- 独立 key 占位方案依赖 `resolveTextureKey()` 被正确使用；硬编码真 key 的代码会是「开发期立刻看见」的 `__MISSING` 纹理，但仍需 `architecture.test.ts` 的字面量扫描兜住。
- C1 事件总线终稿归 D1（本稿为 v0 提案），若 D1 冻结版改动事件名或载荷，D3 表现层与 D4/D5 订阅方需要跟随迁移。

# 六、评审团挑出的最佳想法（已并入上文）

- 单位化血量（hpMode: shots / ttkSeconds + loader 派生）：设计值以「几发击杀」「几秒击杀」表达，D1 改武器时敌人数值自动跟随，平衡讨论从「拍脑袋填血量」变成可核算的公式。
- 帧伤账本三条不变式 + nextTickAtMs 不追赶 + sourceId 单调不复用：把「切标签页回来爆发几百次结算」「池复用串味」这类经典玄学 bug 变成有 Vitest 锁死的定义行为。
- 分裂链只降表现不降生成：软/硬阈值（180/260）只削减顿帧、粒子、字号等特效，永不丢弃实体——玩法语义在任何性能档位下完全一致。
- 肉盾「全额冲击 + 1 次残伤 tick」语义：D1 子弹逻辑零特判（接触即消耗），同时完整保留帧伤账本的测试覆盖面（每发恒 13 点，TTK 可精确核算到 10.0s）。
- JuiceDirector 全局预算（顿帧滚动 500ms 窗口 ≤12% + 各表现通道频率表）：把「爽」工程化成可配置预算，群体混战时自动降档而不是堆叠失控。
