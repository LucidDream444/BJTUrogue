> 《人员分工方案》§三 把「UI 视觉规范」与「UI 公共控件」列为 D4 的输出，
> §四 又规定「各域界面必须基于公共控件搭建」。**这一页是那句话的落地说明。**
>
> 可执行的那一份在代码里：[`client/src/domains/meta/ui/theme.ts`](../client/src/domains/meta/ui/theme.ts)
> （颜色 / 字号 / 间距）与同目录的 `Button` / `Card` / `Slider`。**本页不是真值，代码是。**

别的域**可以 import 它们，但不要改它们** —— 要加状态 / 样式，找 D4。

## 二、四条硬规则

**1. 颜色、字号、间距一律走 `THEME`。** 界面代码里出现 `0x1a1a22`、`'#ffffff'`
或 `'14px'` 这种字面量，就是在制造第二份视觉规范，而两份规范一定只剩一份是对的。

**2. 分层靠创建顺序，别给覆盖层加正的 `setDepth()`。** 见下面第三节。

**3. 场景里的订阅必须成对。** 在 `create()` 里 `on()` / `subscribe()`，就**一定要**
保存返回的退订函数并在 `SHUTDOWN` 里调用。`core/events.ts` 的 `TypedBus` 与
`ProfileStore.subscribe()` 都返回退订函数。匿名函数传给 `off()` 会静默失败。

**4. `Scale.RESIZE` 下，窗口尺寸就是画布尺寸。** 任何界面都要监听
`Phaser.Scale.Events.RESIZE` 并重排，否则拉大窗口之后控件留在原地。

## 三、⚠️ 弹层：这个坑真踩过

弹层（设置 / 说明 / 退出确认）是**叠在主界面之上**的，所以有三层：

```
主界面对象  →  压暗矩形（挡住下层点击）  →  弹层自己的控件
```

**这三层的顺序只由创建顺序决定**：Phaser 的命中判定取"显示列表里最靠后的那个"
（`topOnly` 默认开着），而同深度下列表顺序就是创建顺序。

所以：**给压暗矩形一个正的 `setDepth()`，它就会跑到弹层控件上面去，弹层里的按钮
全部点不中** —— 而且**看起来完全正常**：渲染上也被盖住了，面板把内容整块遮住，
两边还都是深色，连截图上都看不出来。

这个坑是 2026-10-14 在真实浏览器里点出来的（滑杆拖不动、关闭按钮没反应，
而 `typecheck` / `lint` / 单测 / 静态截图四条全绿）。记录见 `持续更新10.14.md`。

## 四、输入

- **全屏 / 指针锁定必须写在用户手势处理函数里**，不能在加载时自动触发
  （`AGENTS.md` §九 第 3 条）。全屏按钮在 `pointerup` 触发；设置状态只跟随
  `Scale.Events.ENTER_FULLSCREEN` / `LEAVE_FULLSCREEN` 更新，不能点击后先写死。
- **多个场景同时活着时，各自抢键盘。** 上层场景要
  `this.input.keyboard.enabled = false` 让位，否则按一下 Esc 会同时触发两边
  （Phaser `KeyboardPlugin` 类注释里给的正是这个办法）。
- **音频要等一次用户点击才能解锁**（所有浏览器通用）。主菜单的那一次点击是
  全游戏唯一的机会。

## 五、占位期的视觉约定

- **没有美术资源时用几何图形 + 文字**（`add.rectangle` / `add.graphics` / `add.text`），
  **不引入任何 texture key** —— 代码里出现 texture key 就是绕过了资源清单
  （`AGENTS.md` §六，有架构测试守着）。
- **"这里还没有东西"用虚线框**，别用实线框：实线框看起来像"图没加载出来"，
  虚线框才是"本来就还没有"。
- 画布里的文字**不支持 Markdown**：写了 `**加粗**` 就会原样显示星号。
