# 局外成长设计（MVP 版）

> 归属：**D4 局外成长与存档**。版本：**MVP 草案**，2026-10-14。
>
> ⚠️ **这一版只够演示。**经济曲线、角色定位、技能体系都还是最简形态，
> 里面标了「待定 / 待补充」的地方是**故意留白**，不是漏写。
> 数值全部在 [`client/public/config/meta.json`](../client/public/config/meta.json)，
> 本文只讲**为什么这么设计**，不重复抄数字（抄了就会漂）。

---

## 一、经济

| 项 | MVP 的决定 |
|---|---|
| 币从哪来 | **对局中获取**：击杀 / 清房 / 到达层数，三个来源相加 |
| 对局中能不能花 | **不能**。对局里不消耗任何货币 |
| 币的唯一用途 | **带出对局**，在局外升级角色、升级技能、解锁角色与技能 |
| 死亡惩罚 | **不丢币**。结算只加不减（这一条写成了不变式，有单测钉着） |
| 通关额外奖励 | **没有**（本期不做） |

**为什么"只加不减"要写成不变式：**"死亡不清空"是玩家能感知的承诺，
而它最容易在后期被某个"复活扣一半币"之类的机制悄悄破坏。
所以加减币集中在一个函数里（`progress.ts` 的 `settleRun`），
加/扣都必须写在那里 —— 散在界面里的话，这条承诺就没有地方保证了。

**待定：**

- 三个来源的**权重**还没试玩过（现在击杀 1、清房 5、层数 20 是拍的）。
- 一局大概该挣多少币、升满一个角色要几局 —— 没有节奏目标，等试玩。
- 通关是否给额外奖励（大概率要给，否则"打完"和"打一半死"差别只有层数）。

## 二、局外成长的三条路径

```
币 → ┬─ 升级角色（提数值）
     ├─ 升级技能（提数值，将来还有新效果）
     └─ 解锁角色 / 技能
```

### 2.1 升级角色

**MVP 只做一个角色**（`student` / 新生），成长线三条：

| 成长线 | 每级 | 满级 | 说明 |
|---|---|---|---|
| 生命上限 | +20 | 10 级 | 最直观的那一条，演示首选 |
| 能量上限 | +10 | 10 级 | 战斗侧的能量池就是射击资源（`combat.json` 的 `maxStamina`）；这条成长线**还没接上去** |
| 护甲 | +1 | 5 级 | 减伤公式**待定**（现在只是个数字） |

成本曲线：**第 L+1 级 = `round(baseCost × costGrowth^L)`**，
两条线各自有 `baseCost` / `costGrowth`，所以可以做成"前期便宜、后期陡"。

**待补充：**

- 三条线的**强弱关系**没有依据（现在纯粹按"生命最常用所以最便宜"拍的）。
- 护甲到底怎么减伤、有没有上限，要等 D1 的战斗结算定。
- 角色满级之后怎么办（现在就是到头了）。

### 2.2 升级技能

**MVP 只做一个技能**：`rapid_fire`（快速击发），成长线一条 —— **攻速 +5%/级，10 级**。

**待补充：**

- **设计上「一个角色可以选择多个技能」，这一版没做。**现在的规则是
  **"解锁即生效"**：`profile.unlocks.skills` 里的技能全都算数。
  要变成"选几个装上"，需要一个装备/选择界面，以及"角色能带几个"的容量规则。
- 技能只有数值、没有新效果。你说的"升级技能除了数值还可能有新效果"——
  效果类的技能（位移、护盾、连锁）连框架都还没有。
- 攻速加成的**上限**没定（现在线性叠加，10 级 = +50%）。

### 2.3 解锁

| 项 | 状态 |
|---|---|
| 解锁状态存哪 | 档里 `unlocks.characters` / `unlocks.skills` |
| 解锁门禁 | 主菜单的角色卡：未解锁的点了只提示，不切换选择 |
| 解锁价格 | 在 `meta.json` 的 `unlockCost` |
| 购买解锁 | **已接上**：升级页的「可解锁」一段，花币解锁 |
| 解锁条件 | **只有钱**。原需求提到"解锁条件展示"，本期没有别的条件 |

**⚠️ MVP 的 3 个可解锁角色都是占位**（体育生 / 图书委员 / 社团长）：
它们**能解锁、能选中，但数值与新生完全相同**（`base` 是抄的、成长线是空的）。
这不是 bug，是"角色定位与差异化设计"还没做 —— 见下面的待补充。

**待补充：**

- **角色定位与差异化设计**（D4 的设计输出，最大的一块空白）。
- 解锁是不是该有**进度条件**（"通关一次"“到达第 3 层"），而不只是攒钱。
- 技能也走解锁，但 MVP 唯一的技能是开局就给的，所以这条路径**没被演示过**。

## 三、界面与数据

| 界面 | 在哪 | 说明 |
|---|---|---|
| 主菜单 | 需求 §4.1 | 角色卡（含已解锁/未解锁）、难度三选一 |
| 角色升级页 | 需求 §4.4（简化） | 金币 + 成长线 + 可解锁，**没有立绘/武器面板/技能选择** |
| 结算界面 | 需求 §4.6 | 结果 / 到达进度 / 击杀 / 清房 / 本次所得 / 当前总计 |
| 暂停菜单 | 需求 §4.3 | 含当前角色数据（升级次数 = 该角色名下所有成长线的级数之和） |
| 奖励选择界面 | 需求 UC04 | **只有壳子**，奖励池内容归 D1 |

**数据形状**（`client/src/domains/meta/profile/types.ts`）：

- 成长线的键是 **`"<归属者>:<成长项>"`**（例如 `student:maxHp`、`rapid_fire:attackSpeedPct`）。
  角色与技能共用同一个字段、同一套代码 —— 差别只有"归属者是谁"。
- 所有存档带 `schemaVersion`（红线 3）；读到自己看不懂的版本**不覆盖**，
  原文进 `bjtu-rogue:profile:backup`，另起一份新档。

## 四、这一版**没做**的（按优先级）

1. **战斗侧要消费成长结果**：`effectiveStats()` 算出了生命/能量/护甲/攻速，
   但**目前没有任何调用方**（D1）。
2. **角色定位与差异化设计**（D4 最大的空白）。
3. **技能选择/装备**（多技能）。
4. **奖励池的真实内容**（D1）。
5. 解锁的进度条件；护甲减伤公式；经济曲线的试玩校准。
6. `upgrades` 的键语义变过一次（角色 id → 复合键）**但没有升 schema 版本、
   也没有迁移**：旧档里的键会被保留但读不出等级。v1 从没发给玩家，影响只在开发机，
   但下次改字段语义时**必须升 v2 + 补迁移**。
7. 本表 `meta.json` 的**字段定义按契约 C2 归 D2**，目前由 D4 起草、**待 D2 过目**。
