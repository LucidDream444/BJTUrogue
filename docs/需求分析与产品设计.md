**需求分析与产品设计文档**

## 1. 项目背景与业务问题

### 1.1 项目背景与定位

《课后勇者：异次元校园》是一款面向大学生群体的2D 俯视角轻量化地牢闯关游戏，主打碎片化休闲玩法，适配学生课后、宿舍休憩等零散空余时间，主打单局短时冒险体验。

游戏核心玩法参考经典地牢射击机制，沿用**移动射击、分房间闯关、随机道具掉落**的核心体验，所有角色、场景、道具、美术素材均为原创设计，保证内容独立性。

游戏核心游玩循环清晰闭环：**进入随机地牢→清理房间怪物→选取对局奖励→挑战关卡首领→对局结算、重复闯关**，兼顾操作手感与重复游玩的趣味性，适配长期轻量游玩。

题材上聚焦校园特色，弱化复杂的校园模拟系统，专属场景元素塑造校园氛围感，风格轻量化、辨识度高。

项目首版定位**单人本地离线游玩**，无联机、复杂养成、社交系统等冗余内容，核心目标为打磨优质战斗手感、优化关卡随机性与奖励机制，验证游戏核心玩法的趣味性和重复游玩价值，为后续版本迭代夯实基础。

> **2026-10-22 后续版本补充：** 首版定位不变，仍要求无网络可完整游玩。后续版本规划云端存档，用于跨设备恢复角色解锁、技能等级、金币与统计；战斗核心继续采用本地优先，不等待网络。接口与冲突规则见 [`云存档接口草案.md`](云存档接口草案.md)。

### 1.2 调研依据与设计判断

| 调研发现（44 份答卷） | 对本项目的启示 |
|---|---|
| 50% 首选动作闯关；45.45% 最看重战斗爽快感。 | 以即时战斗为主，优先保证操作响应、命中与受击反馈。 |
| 5—10 分钟与 20 分钟以上的偏好均为 31.82%。 | 时长需求存在分化；结合校园场景，先验证 5—10 分钟短局，而非认定所有人都偏好短局。 |
| 70.45% 只需简单文字引导；54.55% 偏好中等难度。 | 少讲规则、多给短提示；普通难度为基准，提供更宽容的入门选择。 |
| 65.91% 期待局外永久养成；56.82% 期待局内临时养成。 | 局内用奖励组合制造变化，局外用少量解锁保留目标感。 |

### 1.3 要解决的问题

**时间不合适。** 长流程容易与课后安排冲突；以短局和随时暂停降低时间负担，不用每日任务要求玩家持续上线。

**上手和失败成本高。** 提示不清、难度突升容易让新手退出；用简短引导、攻击预警和入门难度降低挫败感，死亡不清除已获得的永久解锁。

**重复游玩缺少变化。** 仅更换敌人数值难以支撑重玩；让房间、武器与奖励组合产生差异，同时保障基础武器可用，避免全靠运气过关。

## 2. 用户角色与需求

### 2.1 用户类型与维护职责

系统面向两类使用者：课后想放松的大学生玩家，以及负责更新和维护的项目组成员。玩家按经验细分，维护人员按工作职责细分；同一名组员可兼任多项职责，不要求为每项职责开发独立账号。

| 角色 | 场景 / 目标 | 主要需求与操作边界 |
|---|---|---|
| 轻度休闲玩家 | 课后、宿舍休息时短暂放松。 | 快速开局、5—10 分钟短局、随时暂停；不希望被打卡或长流程绑住。 |
| 地牢游戏新手 | 首次试玩，尚不熟悉操作和死亡规则。 | 短提示、入门难度、清晰预警。 |
| 动作闯关爱好者 | 反复挑战，尝试角色和奖励搭配。 | 操作反馈明确；查看进度与解锁，不靠纯数值碾压。 |
| 内容配置人员 | 调整关卡、敌人、武器和掉落。 | 编辑并校验配置，预览效果；只能提交候选内容，不直接覆盖发布版本。 |
| 技术维护人员 | 排查崩溃、卡顿和存档问题，发布修复。 | 读取诊断日志、修复缺陷、备份版本与回退；不能擅自读取玩家个人文件。 |
| 测试人员 | 复现反馈，检查新内容是否破坏旧功能。 | 使用测试存档，验证战斗、结算、解锁和更新兼容性；记录复现步骤与结果。 |

### 2.2 玩家需求与交互要求

| 编号 / 用例 | 触发场景 | 预期结果与限制 |
|---|---|---|
| UC01 查看操作说明 | 首次游玩或忘记操作时。 | 可跳过、可再次查看；说明移动、攻击、交互和死亡规则，不强制重复教学。 |
| UC02 开始闯关 | 从主菜单开始新一局。 | 确认已解锁角色和入门 / 普通难度后进入地牢；攻击、命中与受击反馈清楚。 |
| UC03 暂停 / 继续 | 临时有事，需要中断游玩。 | 敌人、子弹、伤害和战斗计时一并停止；继续时恢复原状态。 |
| UC04 选择局内奖励 | 清房或触发奖励机会时。 | 先查看效果再确认选择；组合影响本局打法，临时效果不带入下一局。 |
| UC05 查看结算 | 通关或死亡后。 | 展示结果、到达进度与所得，保存永久解锁；可返回主菜单或再来一局。 |
| UC06 查看局外解锁 | 想知道已获得内容和后续目标。 | 区分已解锁、未解锁及条件；已获得的永久解锁不因死亡清除。 |
| UC07 导出问题反馈 | 发现卡顿、异常或规则不清。 | 填写问题及复现步骤，确认后导出反馈包，自行交给项目组；不自动上传日志。 |

**依据：** UC01 对应 Q11 简短引导偏好；UC02、UC04 对应 Q4 战斗反馈及 Q6—Q9 角色、养成、时长与难度诉求；UC05、UC06 对应 Q7、Q12 成长与失败反馈。暂停、反馈及维护需求为本组补充，需试玩验证。

### 2.5 流程

**玩家流程：** 主菜单 → 选择角色与难度 → 战斗与奖励 → 通关 / 死亡结算 → 重开或返回。主动退出须确认本局临时进度丢失；保存失败应提示重试，不显示“已保存”。

**维护流程：** 接收反馈 → 定位问题 → 修改配置或代码 → 测试验证 → 发布修复；出现严重问题时停止发布，检查兼容性后回退。维护入口仅供项目组使用，普通玩家不能在游戏界面修改配置。

## 3. MVP 范围与优先级

### 3.1 明确产品目标

本产品面向课后想放松的大学生，需解决三类痛点：

1. **时间不合适**——课后时间零散，长流程游戏易与学习安排冲突，玩家不愿被每日任务绑定；
2. **上手与失败成本高**——新手不熟悉操作与死亡规则，提示不清、难度突升容易劝退；

<!-- PDF 第 4 页 -->

3. **重复游玩缺少变化**——仅更换敌人数值难以支撑长期游玩，玩家很快失去兴趣。

**产品价值：**

- 以 5—10 分钟短局与随时暂停，适配碎片化时间；
- 以即时战斗的爽快反馈、简短引导与入门难度，降低上手与失败成本；
- 以随机地牢与武器、奖励组合的差异，提供重复游玩的变化。

**此前如何满足需求：** 此前用户多通过长流程动作游戏、短视频或休闲卡牌打发碎片时间，前者与课后安排冲突、上手门槛高，后者缺少操作爽感与成长目标。

**一句话目标：** 打造一款面向大学生的2D 轻量地牢闯关游戏，以5—10 分钟单局、可随时暂停、随机可重玩，满足课后碎片化放松需求。

### 3.2 定义用户行为路径

**主路径：**

1. 进入主菜单；
2. 查看操作说明（首次游玩可跳过、可再次查看）；
3. 选择角色与难度（入门 / 普通）；
4. 开始闯关：移动射击、清理房间怪物；
5. 清房后触发局内奖励三选一，查看效果后确认；
6. 击败关卡首领，或中途死亡；
7. 结算：展示结果、到达进度与所得，保存永久解锁；
8. 返回主菜单查看局外解锁，或再来一局；
9. 全程可暂停 / 继续；主动退出需确认本局临时进度丢失。

**维护路径：**

接收反馈 → 定位问题 → 修改配置或代码 → 测试验证 → 发布修复（必要时回退）。

### 3.3 根据用户路径罗列产品功能

团队头脑风暴的功能清单如下（尽量丰富，供后续收敛）：

**玩家侧：**

- 主菜单：开始闯关、查看解锁、查看操作说明、退出；
- 说明：移动 / 攻击 / 交互 / 死亡规则教学，可跳过、可再次查看；
- 选角色与难度：角色选择、入门 / 普通难度；
- 战斗：移动、射击、攻击命中、受击反馈、敌人AI、关卡首领；
- 随机：房间布局、怪物分布、首领的随机生成；
- 局内奖励：三选一奖励、查看效果后确认、组合影响打法；
- 结算：通关 / 死亡结算、到达进度、所得展示；
- 局外解锁：永久解锁、死亡不清除、解锁条件展示；

- 暂停：暂停 / 继续、退出确认；
- 其他：攻击预警、武器 / 道具多样性、音效、美术打磨。

**维护 / 测试侧：**

### 6.2 迭代规划与运维要求

根据课程要求，第6—15 周为持续开发与运维阶段，至少完成3 轮迭代。迭代规划如下：

| 迭代 | 周次 | 迭代目标 | 核心内容 | 退出标准 |
|---|---|---|---|---|
| 迭代1 | 第6—8 周 | 核心循环可玩 | 战斗核心、随机地牢、三选一奖励、暂停 | 单局可完整跑通，无阻断性缺陷 |
| 迭代2 | 第9—11 周 | 局外闭环与内容扩充 | 首领、结算、永久解锁、多角色/难度、武器多样性 | 通关/死亡闭环完成，P1 功能可体验 |
| 迭代3 | 第12—15 周 | 测试、优化与发布 | 集成/系统/性能/非功能性测试、日志与反馈包、回退机制 | 严重缺陷清零，发布候选版RC 通过验收 |

**运维要求落实：**

第6 周起建立诊断日志，记录版本、错误类型与关键游戏事件。<br>第12 周前完成测试存档、反馈包导出、版本发布与回退机制。<br>每次迭代保留上一稳定版，回退前检查存档兼容性，不用旧版强行覆盖新存档。<br>维护入口仅供项目组使用，普通玩家不能在游戏界面修改配置。

| 术语 | 英文/缩写 | 定义 |
|---|---|---|
| 肉鸽 | Roguelike | “Roguelike”的中文社区音译简称，源自 1980 年游戏《Rogue》。核心特征通常包括随机生成、单局循环、死亡重开、局内成长与地牢探索。 |
| 肉鸽莱特 | Roguelite | 保留肉鸽的随机生成与局内成长，但弱化永久死亡惩罚、增加局外永久解锁的轻量变体。本项目更接近 Roguelite。 |
| 随机种子 | Seed | 决定随机地牢生成结果的参数；同一种子可复现同一布局，便于测试与问题复现。 |
| 2D 俯视角 | Top-down 2D | 摄像机从上向下俯视的二维画面表现方式 |

| 单局/局内 | Run | 从进入地牢到通关或死亡结算的一轮完整游玩 |
| 局外 | Meta | 单局结束后的主菜单、解锁、设置等跨局系统 |
| 永久解锁 | Permanent Unlock | 结算后保存、死亡不清除的跨局内容 |
| 局内临时养成 | In-run Upgrade | 仅本局生效、结算后不带入下一局的奖励效果 |
