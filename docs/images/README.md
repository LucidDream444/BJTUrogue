# `docs/images/` — 文档配图

这里放**文档正文引用的图片**。图片是**从代码生成的**，不是手画的 ——
所以每张图下面的「怎么重截」那一行比图本身重要：代码一改，图就过期，
而过期的配图**不会报错**，只会让下一个人照着错的样子做。

> 美术资源**不在这儿**。真图片在 `client/public/assets/`（那是 D4 的管线，
> 命名规范见那边的 README）。这一目录只放「文档里嵌的说明性截图」。

两张图都出自同一个场子 `?arena=d1d2_rooms`（`client/src/test/arenas/joint/`），
拍的是**同一间教室的两种观感** —— 两档之间只差一次 `L` 键，别的什么都没动，
所以它们可以并排比较。正文引用在 [`../地牢生成设计.md`](../地牢生成设计.md) §7.2。

---

## `d2_classroom_look.png` — D2 自己的观感

**一间教室在 D2 这套画法下应该长什么样** —— 给美术定调子、给 D1 接家具用。

地砖、色块桌椅、墙、门框、黑板、窗、盆栽全是 `_classroomLook.ts` 的
`drawClassroomLook()` 画的（`layers: 'full'`）；画面里**只有桌椅与门来自地图数据**
（`Room.obstacles` / `collidersOf().barriers`），装饰**不在任何字段里** ——
D1 的子弹和 D3 的寻路都不知道它们存在。

## `d1_classroom_look.png` — D1 那三张手绘关的观感

**同一间教室，铺上 D1 的手绘关**（`L` 键第二档）。这是「教室的场景也按 D1 的」
那一档的成品样子，也是 D1 的 `CombatSession` 真跑起来时玩家看到的画面。

| 画面上 | 谁画的 |
|---|---|
| **整间教室**：木地板、地毯、阳光、墙、黑板、窗、书架、盆栽 | **D1 手绘关的原图**（`prepareFurnitureTextures()` 的 `floorKey`，桌椅已经挖掉了，整块铺进来） |
| 课桌 / 椅子的样子 | **D1 手绘关**里那张桌椅贴图（按多边形切成「桌」和「椅」两块） |
| 课桌 / 椅子的**位置与大小** | **D2 的地图数据**（`Room.obstacles` 的矩形，一格不差） |
| **门**（门洞与门扇） | **D2 的观感层**（`layers: 'doors'`） |

⚠️ **这一档是「贴图」，不是「几何」。** 整间教室连四周的墙都是画上去的，判定仍旧是
D2 那些矩形（`B` 键切到碰撞箱那一层就能对照）：画上的地板边界与 D2 的墙内沿严丝合缝，
而墙、柜子、盆栽这些**看得见未必撞得到**（画上贴着墙的那个书柜就是穿得过去的）。
**真美术不要照着它画** —— 手绘关那三张图是**成品美术**，不是占位；
也要注意它和 `d2_classroom_look.png` 的桌椅不是同一个形状
（D1 的桌椅贴图比 D2 的判定框略小一圈，这是 `_d1Scenes.ts` 文件头记下的取舍）。

两处**已知的**画法偏差，看的时候别当成 bug：桌子按宽度铺满两格时，桌腿会伸进
椅子那一排约 7px；房间的长宽比是**横竖各拉一次**的（D2 的房间有三种宽、手绘关
只有一种），所以同一张画在窄房间里会显得"瘦"一点 —— 取舍写在 `_d1Scenes.ts`
文件头的「四处已知的偏差」。

## 怎么重截

两张图都是**跑着的场子**的截图，所以先起 dev server（**端口以实际输出为准** ——
5173 被占时 Vite 会自动换）：

```bash
cd client && npm run dev
```

然后在**真浏览器**里打开 `http://localhost:5173/test.html?arena=d1d2_rooms`，按顺序：

| 想要哪张 | 按什么 |
|---|---|
| `d2_classroom_look.png` | `C`（模拟清图，画面里那一堆怪就没了）→ 等三选一出来 → 点一张卡片 → 截图。**观感默认就是 D2 这一档**，不用按 `L` |
| `d1_classroom_look.png` | 接上一步，按一次 `L` —— 提示行会变成「观感：D1 手绘关（整间教室都是那张画，只有门是 D2 画的）」，截图 |

要换一间房再拍：`F` 过门（门前那扇开了才过得去），三间依次是**教室 / 实验台 / 教室（夜）**，
三张手绘关图一一对应。

⚠️ **两张图都带着 HUD**（左上三条、右上小地图、右下读数），这是我们**收不掉**的：
场子是自己 `create()` 的，读数与提示是它的一部分。嫌乱可以按 `M` 收掉小地图，
`B` 收掉碰撞箱那一层 —— **读数没有开关**。

⚠️ 「清图 → 三选一」那一步不能省：不清图的话，画面里站着 5 只怪（还有血条与数字），
而这张图是给美术看**家具与地面**的（顺带说一句，三选一那张卡片是 DOM 覆盖层，
**手机截图以外的自动截图工具一律要先把它点掉**，否则整张图都是卡片）。

### 无头（`msedge --headless`）那一版只能拍到第一帧

```bash
"/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" \
  --headless=new --disable-gpu --no-sandbox \
  --window-size=1280,720 --virtual-time-budget=12000 \
  --screenshot="C:\...\docs\images\d2_classroom_look.png" \
  "http://localhost:5173/test.html?arena=d1d2_rooms"
```

这条**能出图，但和图库里的两张不一样**：无头跑不出按键（`--virtual-time-budget` 会冻住
虚拟时钟，游戏只走十几帧，而且合成按键到不了 Phaser 的键盘插件），所以拍到的是
**开局第一帧**：房间没清、怪还站着、门是红的。要图库里那种干净样子，
得走上面那条真浏览器 + 按键的路（或者在 CDP 里 `emit('keydown-C')` 那种）。

> ⚠️ 走 CDP 的话：`Emulation.setDeviceMetricsOverride` 设的视口**是跟着 websocket 连接走的**，
> 连接一断就还原成窗口的自然尺寸。所以「设视口」和「截图」**必须在同一个连接里**做完 ——
> 分成两条命令跑，第二张图会是另一个尺寸，和第一张对不齐，而且**不报错**。
> 世界尺寸跟着视口走（`取景框 760×400 → 世界 1280×721`），所以两张图得在同一个视口下拍。
> 图库里这两张是 `1280×721`（读数行里能核对）。

四条已经踩过的坑，别再踩一遍：

1. **`--screenshot=` 必须给绝对 Windows 路径**（`C:\...`，不是 `/d/...`，也不是相对路径）。
   给相对路径时 Edge **一声不响地不生成文件** —— 没有报错，只有一个空目录。
2. **不要加 `--force-device-scale-factor`。** 加了之后游戏世界**只渲染在画布左上角一角**，
   看起来活像「布局坏了」，其实只是缩放和 `canvas` 尺寸对不上。
3. **`--virtual-time-budget` 会冻住虚拟时钟**，所以无头图里那行 `生成 <0.1ms` 是假数
   （见 §7.3「已知的读数陷阱」）。截图里其它读数是真读数。
4. **CDP 报的画布高度会多 1px**（`height: 720` 得到 `innerHeight` 721）——
   拿它去和 720 高的参考图比像素会冒出一堆假差异，平移也对不齐。

换种子重截：URL 上加不了（这一场用 `N` 键换），要固定某一颗的话，
改 `client/src/test/arenas/joint/d1d2_rooms.ts` 里 `seedIndex` 的起点，
或者照 `_shared.ts` 的 `D2_SEEDS` 顺序数（小地图标题里印着「牌 N/6 · 种子 xxxxx」，
右下角的读数里也有同一颗种子）。**图库里这两张是牌 4/6 · 种子 837。**
